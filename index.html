3 · Git

Your project’s time machine

Git remembers meaningful snapshots of your work. A snapshot is called a commit. It lets you see what changed and safely try ideas.

Try to explain it:

Why might snapshots be more useful than endlessly copying folders called “final-final-2”?

Commits have a message, a history, and can be compared or restored. That makes your choices visible instead of mysterious.
4 · GitHub

Your project’s shared home

Git runs on your computer. GitHub is an online place where a Git project—called a repository or “repo”—can live, be shared, and be checked automatically.

When your GitHub account is connected, we’ll create a small repo together and practise: change → review → commit → upload.

5 · CI/CD

A robot checklist, then a delivery service

Continuous Integration (CI) means every proposed change gets checked automatically—like spelling and basic “does it still work?” checks. Continuous Delivery/Deployment (CD) means a change that passes those checks can be prepared or sent live consistently.

In your project

  1. You edit this page.
  2. You save a checkpoint with Git.
  3. You upload it to GitHub.
  4. GitHub Actions runs a simple check.
  5. A passing version can be published.
Key idea

CI/CD does not replace you. It catches repeatable mistakes and turns publishing into a calm, predictable process.
